# Move SMock to .NET 11 and prepare prerelease 2.7.0-preview.1

## Overview

Add .NET 11 support and drop the .NET versions that are out of Microsoft support (.NET 8 and .NET 9, end of support 2026-11-10). Keep .NET Standard 2.0 and all .NET Framework targets (4.6.2 to 4.8.1). Update every NuGet package. Use the MonoMod prereleases that add `net11.0` and runtime-async detour support. Modernize the code with C# 14/15 and .NET 11 features, with no public API or behavior change. Prove that SMock hooks runtime-async methods. Update docs and CI. Prepare the prerelease `2.7.0-preview.1`, because MonoMod is still in prerelease. The final result of the run is a pull request into `master`. A stable SMock 2.7.0 follows when MonoMod ships stable versions with `net11.0`.

## Development Approach

- **Testing approach**: Regular (code first, then tests)
- Complete each task fully before moving to the next
- Decisions made in this plan:
  - The library keeps `netstandard2.0` and all .NET Framework TFMs, and adds `net11.0`.
  - Test, common and benchmark projects target .NET Framework 4.6.2 to 4.8.1, `net10.0` and `net11.0`.
  - Release is the prerelease `2.7.0-preview.1` (tag `v2.7.0-preview.1`), because MonoMod is still in prerelease. Do not suppress `NU5104`. The goal of the run is a pull request into `master` with this prerelease version. Stable `2.7.0` comes later, when MonoMod is stable.
  - MonoMod moves to the prereleases first, before any `net11.0` test. The .NET Framework TFMs also use MonoMod.Core 1.4.0-prerelease.3 with `DetourFactory.Current.CreateDetour`, the same hook code as netstandard2.0. MonoMod.RuntimeDetour and its `Hook` class are removed, because RuntimeDetour 25.x `Hook.CheckSupported` rejects generic methods and methods on generic types. The run cannot execute .NET Framework tests (macOS) and cannot push during the run, so the Windows gate is the pull request's CI. If the .NET Framework tests fail there, the fallback is MonoMod.RuntimeDetour 22.7.31.1 with `Hook` for the .NET Framework TFMs only, as a follow-up commit on the pull request branch.
  - NUnit goes to version 5. There is no fallback to NUnit 4.6.1.
  - Code modernization comes before the runtime-async task, so the new tests run on modern code. It has no public API change and no behavior change.
  - Hooks on runtime-async methods must work for `Task`, `Task<T>`, `ValueTask` and `ValueTask<T>`. There is no "document the limitation" fallback, with one exception that the user accepted on 2026-11-25 (by default after 15 min without reply) for this preview: generic method instantiations that return `Task`, `Task<T>`, `ValueTask` or `ValueTask<T>` (for example `Task.FromResult<int>`) on the .NET 11 runtime: MonoMod.Core 1.4.0-prerelease.3 throws `NotSupportedException: The method ... is generic` from `Core110Runtime.TryGetRuntimeAsyncInfo` (source comment: "We don't have proper support for this yet", `src/MonoMod.Core/Platforms/Runtimes/Core110Runtime.cs:147` on the `reorganize` branch). This is an upstream MonoMod limitation; SMock documents it, gives a clear error for it, and tests that error. Any other runtime-async hook failure still fails the task.
  - macOS cannot run .NET Framework tests. Run `net10.0` and `net11.0` locally. Build all TFMs locally. Windows CI covers .NET Framework.
  - `async void` is not runtime-async. Keep compatibility tests for it. Assert the runtime-async marker only on `Task`, `Task<T>`, `ValueTask` and `ValueTask<T>` methods.
  - The hierarchical `Mock.Setup` validation parameter is an `Action`. Never pass an `async` lambda to it: it becomes `async void`, and the hook can end before the assertion finishes.

- **CRITICAL: all tests must pass before starting next task**
